# 智伴方舟高校版：交付构想与迭代执行规范

> 版本：1.3 · 2026-09-23。本文是后续开发的任务入口、验收口径和阶段总结。适用于当前 FastAPI + Next.js 项目；现有 AGENTS.md 的数据保留、删除确认约束持续有效。

## 1. 最终成果是什么

交付一个能够供单所高校小范围试用的网页系统。学生在手机浏览器注册、登录、倾诉和使用已有自助工具；工作人员在电脑浏览器登录工作台，查看黄色/红色预警并完成跟进。刷新页面后身份、聊天历史和跟进结果与数据库一致。加载、空数据、服务异常都有明确反馈与恢复路径。

本轮以“已有功能形成可靠闭环”为目标，不扩展社区端、社交广场、支付、诊疗、教务课表采集等业务。沿用 Python 后端、Next.js 前端、SQLite；交付源码、可复跑测试、构建与运行说明，不生成 WAR。

### 用户看到的页面

| 页面 | 成熟交付表现 | 数据/行为来源 |
| --- | --- | --- |
| `/` 首页 | 清晰说明学生/高校工作人员入口，链接均可访问 | 已有落地页 |
| `/login` 学生登录/注册 | 必填校验、重复账号/密码错误可理解；成功进聊天；退出后重新登录正常 | 真实注册/登录 API、Cookie |
| `/chat` 陪伴空间 | 文本发送稳定，中文输入法不误发送，历史加载可恢复，发送中防重复；ASR 回填后由学生确认发送 | 对话、历史、ASR API |
| `/chat` 现有侧栏与工具 | 每日治愈、能量补给电台、正念放松站、学业解压锦囊、情绪碎纸机、电子木鱼、打字发泄墙可操作 | 当前已有实现；外部资源失败应有反馈 |
| 右上角账户设置 | 学校/学号读取正确；学姐/学长选择影响页面和下一次请求；保存范围如实说明 | 身份 API；当前偏好在本浏览器保存 |
| `/admin-login` 管理登录 | G 类账号登录、错误提示、未登录拦截正常 | 管理鉴权 API |
| `/admin` 工作台 | 三个概览块结束加载；学生数按注册学生统计；仅黄/红入池；刷新和优先排序有效；跟进后持久化 | 真实统计、预警、跟进 API |

### 明确当前边界

- 风险分级当前由关键词规则实现，是流程辅助，不能声称已验证医学准确率。
- “正常对话不记录”在当前产品中执行为“不进入预警池”；现有聊天历史仍保存普通对话。任何调整聊天留存策略需单独明确，不在测试时删除历史。
- 开场白的阶段目前按设备时间与月份推断，不是真实个人课表或学校考试日历；不得把推断呈现成已接入教务系统。
- 目前按单校部署验收。管理员接口按高校场景过滤，未实现学校之间的数据隔离；未通过跨校隔离专项前，禁止宣称可供多校共用一个实例。
- 表情文本与轻量校园用语已纳入人设；图片表情包资源、真实课表不是本轮已交付功能。
- ASR/真实 LLM 依赖外部服务；离线兜底成功和模拟服务成功不能作为供应商调用成功的证据。

## 2. 交付清单与完成标准

| 编号 | 交付物 | 完成条件 |
| --- | --- | --- |
| D1 | 当前规范与任务台账 | 目标、范围、验收用例、命令、阻塞项、阶段记录在本文可查 |
| D2 | 可构建的前后端源码 | lint、类型/生产构建、后端契约测试均通过 |
| D3 | 可复跑的整链路验证入口 | 独立临时库、独立端口，运行后生成通过/失败报告，自动停止本次测试启动的服务 |
| D4 | 功能性验收证据 | 浏览器使用真实 HTTP、Cookie、Next 转发、SQLite 完成登录→聊天→预警→跟进；保留失败信息和截图 |
| D5 | 发布候选说明 | 配置模板、启动/健康检查、备份恢复步骤、已知限制与人工验收清单可执行 |
| D6 | 实际环境验收记录 | 真实模型、ASR、手机麦克风、HTTPS、跨设备访问分别留证；未执行标“待验证” |

发布门槛：必测用例全部通过；没有未处理的 P0/P1；正常操作无浏览器未捕获异常、第一方资源 404、非预期 5xx；人为断网、错误密码、错误格式等预期失败有可理解反馈，不能算作“零错误”造假。一次失败修复后必须重跑关联用例和核心闭环。

P0：数据越权/损坏、错误跟进、关键流程完全不可用。P1：主要操作失败、无限加载/等待、重复发送或账号统计错误。P2：文案、布局、反馈等不阻断流程问题。发现 P0/P1 后先处理或明确阻塞，不继续堆叠功能。

## 3. 目标驱动的开发—测试—验证循环

```text
用户目标 → 可观察验收条件 → 核对代码与接口 → 复现/记录问题
    ↑                                            ↓
阶段台账与证据 ← 核心流程回归 ← 定点验证 ← 最小范围实现
                   ↓ 失败
             缺陷定位与修复 → 重跑关联用例
```

每项任务必须记录：任务 ID、目标、前置条件、改动范围、验收步骤、预期结果、实测结果、证据路径、未验证项。状态只使用：待开始 / 进行中 / 通过 / 失败 / 阻塞 / 待真实环境验证。

测试形成三层：①后端契约与权限；②真实前后端浏览器闭环；③外部服务与目标设备人工验收。层与层之间共享同一组业务验收编号；不得用大量不相关单元测试替代业务结果。

开发规则：

1. 先读取本文任务台账和 AGENTS.md，检查当前工作区，保留用户已有改动。
2. 每轮选择一个可闭环目标；先获得失败证据，再修复根因；不凭猜测改全项目。
3. 浏览器核心链路必须连接真实测试后端。对第三方服务的替身、故障注入单独标注。
4. 所有注册、聊天、预警测试只使用独立测试库；默认不访问业务数据库、不调用计费模型。
5. 不删除文件、目录、数据；确需删除时先列精确对象与原因，按 AGENTS.md 等待“确认”。测试运行产物保留，不能自动递归清理。
6. 当前 dev/build 共用 `.next`；正式构建前先检查开发服务。专用验证构建使用独立目录，不覆盖用户的 `.next`。
7. 密钥不写文档、截图或测试报告。测试服务只监听本机，结束仅停止自身启动的进程。
8. 修改页面交互时检查键盘、中文输入法、移动端宽度、加载/失败反馈；沿用现有视觉系统。
9. 验收结束更新本文，不把 mock、未执行、受环境阻塞写成“成功”。不能在核心门槛失败时宣布成熟版完成。

## 4. 功能验收矩阵

| ID | 操作/场景 | 必须观察到的结果 | 验证层 |
| --- | --- | --- | --- |
| F01 | 未登录打开聊天/工作台 | 分别进入对应登录页，无重定向循环 | 浏览器 |
| F02 | 注册→退出→错误密码→正确登录 | 账号可复用，错误明确，成功进入聊天 | 浏览器+API |
| F03 | 空白账号、过短/过长密码、重复注册 | 4xx 业务错误，无后端 500，无新增无效账号 | API |
| F04 | 学生与管理员在同浏览器登录 | 各接口取得正确身份；学生不能调用管理接口 | API+浏览器 |
| F05 | 发送正常消息并刷新 | 单次操作产生一问一答，历史恢复；预警数不增加 | 浏览器+DB |
| F06 | 同一学生先发红风险再发黄风险 | 工作台自动出现两条分级预警；账号总数仍为 1 | 手机视口+桌面视口 |
| F07 | 切换红色优先/按时间 | 红优先置顶；关闭后新黄预警在前；设置刷新保留 | 浏览器 |
| F08 | 标记跟进→刷新→再次打开 | 待处理池移除，服务器记录处理人/时间；重复操作不覆盖首次处置 | API+浏览器 |
| F09 | 工作台加载失败后重试 | 不永久骨架屏；可恢复并显示服务器数据 | 故障注入 |
| F10 | 学姐/学长切换后发送 | 页头、等待提示、请求人设一致；刷新偏好保留 | 浏览器+契约 |
| F11 | 中文输入法 Enter 确认文字 | 不发送；结束输入后 Enter 只发送一次 | 浏览器 |
| F12 | ASR 成功/失败/取消/权限拒绝 | 回填需确认发送；所有结束分支恢复按钮；可再次录音 | 浏览器替身+真实设备 |
| F13 | 治愈语与全部现有自助工具 | 加载/播放/停止/计数/清空输入等已有操作可用；不影响聊天 | 浏览器+人工 |
| F14 | 375px、390px、桌面、横屏 | 无横向溢出，输入和主要操作可触达；无未捕获异常 | 浏览器 |
| F15 | 网络中断/会话失效 | 等待有上限、错误可恢复、登录身份可重新建立 | 故障注入 |
| F16 | 生产构建与同源转发 | 构建通过；真实 `/api` 转发；页面/静态文件无非预期 404/500 | 构建+浏览器 |
| F17 | 真实 LLM/ASR/目标 HTTPS 站点 | 实际返回、超时与失败提示可验证；手机麦克风可用 | 真实环境 |

F06 延迟口径：离线受控测试中，从聊天接口返回到默认 3 秒轮询发现预警不超过 6 秒；选择 10/30 秒时按配置周期另加网络耗时验收。不是服务并发或供应商响应速度承诺。

## 7. 执行命令与证据约定

基础环境：Python 3.12、Node/npm、`backend/requirements.txt`、`frontend/package-lock.json` 对应依赖。浏览器验收使用 Python Playwright，测试依赖在 `scripts/requirements-test.txt`。

首次准备与以后每轮完整验收（项目根目录）：

```powershell
# 已安装依赖时无需重复安装
python -m pip install -r backend/requirements.txt -r scripts/requirements-test.txt
python -m playwright install chromium
Push-Location frontend
npm ci
Pop-Location

# 统一入口：后端契约 → lint → 生产构建 → 真实前后端浏览器 → dev 故障恢复
python scripts/verify_project.py
```

退出码 0 才算本轮自动化通过。入口会打印 `ARTIFACTS=...` 与最终 `REPORT=...`；同时运行以本机 18997 端口锁互斥。测试网站和 API 使用随机空闲端口，均只监听 `127.0.0.1`。全部测试产物保留，不自动删除；不要求演示账号已存在，不读写业务库。

浏览器入口使用 `.next-verify` 和 `tsconfig.verify.json`，由 `ARK_VERIFY=1` 选择，日常启动仍使用 `.next`。Next 可能重生成 `next-env.d.ts` 的路由类型引用，这是编译器产物，正常启动时会按其构建目录重新生成。验证过程中不要手动复用测试端口或运行第二个 `.next-verify` 构建。

| 程序 | 职责 |
| --- | --- |
| `scripts/verify_project.py` | 运行检查、建立/关闭专用服务、生成 JSON/Markdown 汇总 |
| `scripts/acceptance_server.py` | 保护测试库位置，创建专用管理员；隔离外部 LLM/ASR/治愈语 |
| `scripts/browser_acceptance.py` | 手机/桌面浏览器真实核心闭环；不拦截核心 API |
| `scripts/session_acceptance.py` | 双端退出接口故障、无效/过期 Cookie、重新登录和另一端身份保留 |
| `scripts/preference_acceptance.py` | 跨学生账号、旧版/无效人设、禁用存储时双端操作和重新登录 |
| `scripts/check_campus_time.cjs` | 执行实际 TypeScript 时间帮助函数，覆盖 12 个月 × 14 个小时边界 |
| `scripts/interaction_acceptance.py` | dev StrictMode 语音复测、延迟/错误响应/权限拒绝等明确标注的故障注入 |
| `backend/test_contracts.py` | 认证输入边界、重复跟进保护、趋势自然日边界 |
| `backend/test_risk_language.py` | 35 条风险表达规则样例、回复不虚构症状、提示词与分级一致；契约测试逐条验证入池 |
| `backend/test_release.py` | 既有角色、聊天和预警回归 |

旧 `frontend/scripts/ui_release_check.py` 已改为转调统一入口，避免硬编码演示账号并误操作既有预警。

已有检查：

```powershell
python -m py_compile backend/main.py backend/auth.py backend/database.py backend/schemas.py backend/llm_service.py
Push-Location backend
python -m unittest test_release
Pop-Location
Push-Location frontend
npm run lint
# 确认没有共享 .next 的开发服务后执行
npm run build
Pop-Location
```

每次自动化验收生成独立报告目录，保存 `report.json`、`report.md`、构建/服务日志与必要截图。数据库和日志不提交仓库；固定测试程序与本规范纳入版本管理，是否创建提交由用户决定。报告列明第三方替身、预期 HTTP 错误和未验证范围。
