# 管理员端第一批 · 验收标准

> 供 Ark 验收对照用。范围：`/admin` 工作台信息架构改版 + 预警池筛选/视图 + 标记跟进 + 学生端联通 + 接入已有统计/趋势/标签/学生一览接口。对齐 PRD_v2 渐进交付（POOL/ADM 子集），**不做完整 I1 状态机**。只写验收；不写业务实现说明。脱敏遵守 ADR 0002。

## 清单

- [ ] **工作台信息架构改版：概览 + 预警池（桌面优先 ≥1280）**  
  `/admin` 至少分为：**概览**（统计卡 + 风险趋势/标签）与 **预警池** 两大区块（页签或同页分区均可）。桌面宽度 ≥1280 时主内容无横向溢出（对齐 NFR-09 工作台口径）。概览须接入并展示：`GET /api/admin/stats`、`GET /api/admin/risk-trend`、`GET /api/admin/risk-tags`（失败有明确反馈/可重试，不静默空白）。  
  **失败**：仍只有旧三卡+待跟进列表、无趋势/标签；≥1280 横向溢出；接口失败无提示。

- [ ] **预警池：等级筛选 + 待跟进/已跟进视图；红色优先；脱敏摘要**  
  可按等级筛选 **黄 / 红 / 全部**（对应 `GET /api/admin/alerts` 的 `level` 等查询；全部=黄+红，不含 green）。可切换 **待跟进 / 已跟进** 视图（`handled=false|true`）。开启红色优先时 red 排在 yellow 前。卡片展示：账号、等级、标签、**脱敏摘要**、时间；页上标明「脱敏摘要」。**不得**出现学生消息原文（ADR 0002 / SEC-02）。  
  **失败**：无黄/红/全部或待/已跟进切换；排序无视红色优先；出现原文或可点开原文。

- [ ] **标记跟进：现有 handle 接口；跟进后列表更新**  
  「标记已跟进」走现有 `POST /api/admin/alerts/{event_id}/handle`，body 含 `action=follow_up`（可带 note）。成功后该事件从待跟进视图移除（或进入已跟进）；刷新/轮询后状态保持。重复提交按现有幂等语义不报错、不覆盖首次跟进记录。  
  **失败**：跟进不落库；待跟进仍显示；或接口路径/动作与现网不一致导致失败。

- [ ] **学生端联通：yellow/red 入池后工作台可见同一事件**  
  学生在陪伴空间聊天产生 **yellow 或 red** 风险事件后，工作台预警池在轮询周期内可见**同一事件**：学生账号、等级、标签、脱敏摘要、时间与后端 `risk_events` / `GET /api/admin/alerts` 一致。green 不入池。  
  **失败**：学生端已出黄/红但工作台长期不可见；字段不一致（账号/等级/标签/摘要/时间对不上）。

- [ ] **学生一览入口（轻量）：users + 可选 activity/interventions**  
  接入 `GET /api/admin/users`，提供轻量「学生一览」入口（列表或概览内入口即可）。若点开详情，在接口可用时展示 `GET /api/admin/users/{user_id}/activity`、`GET /api/admin/users/{user_id}/interventions`；展示内容**不得**含消息原文（ADR 0002）。接口不可用时有明确失败态，不假装已交付。  
  **失败**：无学生一览入口；或详情带出原文；或接口失败无反馈。

## 本批不验（范围外）

- 认领 / 分派 / 改派（POOL-03）及完整 CASE 状态机（CASE-01）
- 响应时限与超时升级（POOL-02）
- 复评提醒（CASE-03）、结构化跟进记录页（CASE-02 完整版）、结案标注回流（RISK-04）
- 配置页 ADM-03；工作人员子角色 ADM-01；学院范围 POOL-06
- 审计日志页 ADM-05；匿名看板完整指标（ADM-04 超出本批已接 trend/tags 的部分）
- 量表入预警池（RISK-05 / 待 ADR）
- 事件详情页完整证据链（POOL-04 完整版，本批仅卡片级脱敏摘要）
