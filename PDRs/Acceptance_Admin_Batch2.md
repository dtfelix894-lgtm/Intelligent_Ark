# 管理员端第二批 · 验收标准

> 供 Ark 验收团队用。范围：预警池 **事件详情（脱敏）** + **学生分组视图** + **认领雏形**（必验）+ **分派/改派雏形**（尽量验）+ 与学生端/第①批联通。对齐 PRD_v2 POOL-04 / POOL-05 / POOL-03 雏形；脱敏遵守 ADR 0002；分组不去重遵守 ADR 0001。**兼容第①批**：等级筛选、待跟进/已跟进、POST .../handle（action=follow_up）仍可用。只写验收，不写业务实现说明。本批仍**不做完整 I1 / CASE 状态机**。

## 清单

- [ ] **事件详情（脱敏）：摘要/标签/等级/时间/跟进状态，无消息原文**  
  预警池条目可点开进入详情（抽屉或独立路由均可）。详情至少展示：学生账号、等级、标签、**脱敏摘要**、入池/事件时间、跟进状态（待跟进/已跟进等第①批已有口径）；若已认领则展示负责人。页面不得出现学生消息**原文**，不得提供「查看原文」入口（ADR 0002 / SEC-02 / POOL-04）。若后端已有「打开详情写审计」能力，打开详情应落一条审计（谁、何时、哪条事件）；无则本批不强制，但不得为接 activity/interventions 而把含原文的字段渲到工作台（见 PRD Q14）。  
  **失败**：详情缺关键字段；出现原文或可点开原文；接了含原文的接口未剥离。

- [ ] **学生分组视图：按学生聚合展示，组内仍逐条操作；存储不去重**  
  预警池可切换「按学生分组」视图。每组至少展示：学生账号、事件数、最高等级（同组有红则红优先于黄）；可选最早未认领/未跟进时间。分组**只影响展示**；组内事件仍可逐条打开详情、认领、标记跟进。存储层**不合并、不去重**（ADR 0001 / POOL-05 / Q1）；工作台学生计数口径与第①批一致。  
  **失败**：无分组切换；分组后只能整组操作、无法逐条；存储或接口把多事件合并成一条；学生计数口径被改坏。

- [ ] **认领雏形（必验）：待跟进可认领到当前工号；已认领可见负责人**  
  待跟进事件提供「认领」；成功后负责人为**当前登录工号**，列表/详情可见负责人。并发认领时至多一人成功（另一人失败提示「已被认领」类文案，若后端已支持 409 则对齐）。本批无子角色精细权限时，**凡 admin 均可认领**即可。认领后仍可走第①批 handle 标记跟进；不得因认领破坏已跟进视图。  
  **失败**：无法认领；认领后看不到负责人；多人同时认领都成功且无提示；认领后 handle 跟进失败。

- [ ] **分派/改派雏形（尽量验）：可把事件分派给其他工号**  
  **应尽量完成**：心理中心（或本批全 admin）可将事件分派/改派给其他工号；分派后负责人更新并在列表/详情可见。无子角色精细权限时可先「全 admin 可操作」。若排期紧张，可仅交付「认领 + 显示负责人」，但须在实现备注中标明分派未做；**认领为必验，分派为尽量验**。  
  **失败（仅当宣称已做分派时）**：分派后负责人不变；无目标工号选择/输入；分派成功但详情/列表不刷新。

- [ ] **与学生端 / 第①批联通：详情账号等级一致；handle 跟进仍可用**  
  学生端聊天产生 yellow/red 入池后，第②批详情中的账号、等级、标签、脱敏摘要、时间与入池事件及 GET /api/admin/alerts 一致。第①批筛选（黄/红/全部、待跟进/已跟进）、红色优先、标记跟进（POST /api/admin/alerts/{event_id}/handle，action=follow_up）在第②批 UI 下仍可用且列表更新。  
  **失败**：详情与入池字段不一致；第①批跟进/筛选在新 UI 下不可用或状态不同步。

## 本批不做（范围外）

- 完整 CASE 状态机（CASE-01：pending→claimed→… 全链路）及结案标注（RISK-04）
- 复评计划/提醒（CASE-03）、结构化跟进记录完整页（CASE-02 完整版）
- 响应时限与超时升级（POOL-02）
- 配置页 ADM-03、工作人员子角色精细权限 ADM-01、学院范围 POOL-06
- 独立审计日志页 ADM-05（本批仅「有则写打开详情审计」）
- 量表入预警池（RISK-05 / 待 ADR）
- 删改第①批已验收的概览统计/趋势/标签主路径（仅叠详情、分组、认领/分派）
